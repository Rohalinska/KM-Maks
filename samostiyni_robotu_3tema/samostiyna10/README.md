# Звіт із самостійної роботи №10

**Тема:** Стандарти мереж: «IEEE 802» і структура «RFC»  
**Варіант:** №4 (Протокол **SMTP**)  
**Джерело (Datatracker):** https://datatracker.ietf.org/doc/rfc5321/

## 1. Основна інформація про RFC

| Поле RFC | Значення з титульної сторінки |
| :--- | :--- |
| **Номер RFC** | RFC 5321 |
| **Повна назва** | Simple Mail Transfer Protocol |
| **Рік публікації** | 2008 (Жовтень) |
| **Статус документа** | Draft Standard / Standards Track |
| **Автор / Організація** | J. Klensin / Network Working Group (IETF) |

## 2. Перевірка чинності документа

**Висновок:** Документ **RFC 5321 є чинним (Active)**. Він замінив застарілі RFC 2821, RFC 821, RFC 974 та RFC 1869 (поле *Obsoletes*), але сам не має записів у полі *Obsoleted by*.

## 3. Факти з тексту RFC 5321

* **Обмеження довжини командного рядка (Розділ 4.5.3.1.4):** Максимальна довжина будь-якої команди в SMTP (разом із аргументами та `CRLF`) становить чітко 512 байтів.
* **Обмеження довжини імені користувача (Розділ 4.5.3.1.1):** Локальна частина адреси пошти (`local-part` до знака `@`) не може перевищувати 64 байти.

## 4. Підгрупи родини IEEE 802

| Підгрупа IEEE | Область відповідальності |
| :--- | :--- |
| **IEEE 802.1** | Загальна архітектура локальних мереж, безпека, управління та VLAN (802.1Q). |
| **IEEE 802.3** | Стандарти для дротових мереж Ethernet (кабелі, кадри, фізичний рівень). |
| **IEEE 802.11** | Стандарти та протоколи для бездротових мереж Wi-Fi. |

## Контрольні запитання

1. **Proposed Standard vs Internet Standard:** *Proposed Standard* - це перевірений і рекомендований стандарт. *Internet Standard* - це найвищий рівень, який дають тільки після багатьох років масового використання в інтернеті.
2. **Поля «Obsoletes» і «Updated by»:** *Obsoletes* показує старі RFC, які цей документ скасував. *Updated by* показує новіші RFC, які додають дрібні правки, але не скасовують цей документ.
3. **IEEE 802.1 vs IEEE 802.3:** 802.1 відповідає за загальну архітектуру мереж і VLAN, а 802.3 - суто за дротовий Ethernet.
4. **Навіщо перевіряти актуальність RFC:** Технології змінюються, і без перевірки можна прочитати застарілі правила (наприклад, RFC 821 від 1982 року), які давно не використовуються.
