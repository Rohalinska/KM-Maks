## Контрольні запитання

### 1. Конвеєр та його прискорення

* **Що це:** Як конвеєр на заводі. Програма ділиться на кроки (завантажити, розшифрувати, виконати). Процесор робить кілька дій одночасно, але кожну - на своєму етапі.
* **Прискорення:** Максимум у $N$ разів (де $N$ - кількість етапів конвеєра).

### 2. Приклади конфліктів

* **За даними:** Друга команда чекає результат першої (наприклад, спочатку рахуємо `R1 = R2 + R3`, а в наступному рядку вже треба цей `R1`).
* **За керуванням:** Умови `if/else` або цикли. Процесор ще не знає, куди поверне програма, поки не порахує умову.
* **Структурний:** Дві команди одночасно просять одну й ту саму деталь процесора (наприклад, єдину лінію пам'яті).

### 3. Простий конвеєр vs суперскалярність

* **Простий конвеєр:** Стартує чітко **1 команду** за такт.
* **Суперскалярний:** Має кілька паралельних ліній і може запускати **2–4 команди** за один такт.

### 4. Помилка передбачення переходу

Якщо процесор не вгадав напрямок в `if/else`, він **викидає зроблену наперед роботу** (стирає конвеєр) і повертається робити правильну гілку. Це створює паузу в роботі.

### 5. Закон Амдала

* **Суть:** Швидкість програми завжди впирається у її **послідовний шматок**, який неможливо розпаралелити.
* **Наслідок:** Якщо $20\%$ коду виконується суворо в один потік, навіть 100-ядерний процесор не зробить програму безкінечно швидкою.

### 6. Що таке big.LITTLE

Це коли в одному процесорі є два типи ядер:

* **LITTLE (слабкі/економні):** крутять музику чи месенджери й бережуть батарею.
* **big (потужні):** вмикаються тільки для важких ігор чи відео.

### 7. Пересилання (forwarding) та паузи (stall)

* **Forwarding:** віддає свіжий результат обчислень одразу наступній команді «з рук в руки», не чекаючи запису в пам'ять.
* **Stall:** неминучий при читанні з пам'яті (`LOAD`), бо дані з кешу приходять занадто пізно.

### 8. Чому SIMD не прискорює ровно у 4 рази

Бо є додаткова робота: треба розставити дані по порядку в пам'яті, запакувати їх у спеціальні регістри, а хвостики даних доробляти окремо.

### 9. Максимальне прискорення при $f = 0.2$

Формула граничного прискорення:

$$S_{\text{max}} = \frac{1}{f} = \frac{1}{0.2} = \mathbf{5}$$

*Відповідь:* Максимум у **5 разів** (це абсолютна стеля).

## Домашнє завдання

### 1. Закон Амдала (послідовного коду $25\%$, тобто $f = 0.25$)

Формула:

$$S = \frac{1}{f + \frac{1 - f}{p}}$$

* **Для 4 ядер ($p = 4$):**

$$S_4 = \frac{1}{0.25 + \frac{0.75}{4}} = \frac{1}{0.4375} \approx \mathbf{2.29}$$


* **Для 8 ядер ($p = 8$):**

$$S_8 = \frac{1}{0.25 + \frac{0.75}{8}} = \frac{1}{0.34375} \approx \mathbf{2.91}$$


* **Для 16 ядер ($p = 16$):**

$$S_{16} = \frac{1}{0.25 + \frac{0.75}{16}} = \frac{1}{0.296875} \approx \mathbf{3.37}$$

**Висновок:** Додавати більше ядер немає сенсу. Кількість ядер виросла у 4 рази (з 4 до 16), а швидкість піднялася лише з $2.29$ до $3.37$, бо $25\%$ послідовного коду гальмують усе інше (максимальна стеля тут $\frac{1}{0.25} = 4$).

### 2. Тип конфлікту

Код:

```assembly
ADD R1, R2, R3 ; R1 = R2 + R3
SUB R4, R1, R5 ; R4 = R1 - R5
```

* **Тип:** **Конфлікт за даними**.
* **Чому:** Другому рядку `SUB` потрібне число з `R1`. Але перший рядок `ADD` ще не встиг записати результат у `R1`. Процесору доводиться чекати або терміново пересилати значення.


### 3. Приклад з умовою (`if/else`)

Код:

```cpp
if (x > 0) {
    a = 1;
} else {
    a = 2;
}
```

* **Чому це конфлікт за керуванням:** Процесор завантажує команди наперед. Але поки він не перевірить `x > 0`, він не знає, яку саме гілку завантажувати в конвеєр - першу чи другу.
