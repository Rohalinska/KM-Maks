## Контрольні запитання

### 1. Принцип побудови ієрархії пам’яті

Фізичні та економічні обмеження: надшвидка пам'ять (SRAM) дорога, габаритна та споживає багато енергії, тому її роблять малою (L1–L3). Повільніша пам'ять (DRAM, SSD) дешева й містка. Така комбінація дає високу підсумкову швидкість за помірної вартості.

### 2. Часова та просторова локальність

* **Часова локальність (Temporal Locality):** якщо відбулося звернення до комірки пам'яті, з високою ймовірністю до неї звернуться знову у найближчому майбутньому.
```c
int sum = 0;
for (int i = 0; i < 100; i++) {
    sum += i; // Змінна sum використовується повторно на кожній ітерації
}

```


* **Просторова локальність (Spatial Locality):** якщо відбулося звернення до комірки, незабаром буде звернення до сусідніх комірок пам'яті.
```c
int arr[100];
for (int i = 0; i < 100; i++) {
    arr[i] = i; // Послідовне читання сусідніх елементів масиву
}

```



### 3. Способи відображення кешу

* **Пряме (Direct-Mapped):** кожен блок іде лише в один конкретний рядок. Швидко, але багато конфліктів.
* **Повністю асоціативне (Fully Associative):** блок може зайняти будь-який рядок. Без конфліктів, але апаратно складніше.
* **Множинно-асоціативне (Set-Associative):** кеш ділиться на групи (sets). Блок іде у визначену групу, а всередині - в будь-який її рядок. Оптимальний баланс.

### 4. Типи промахів кешу

* **Обов’язковий (Compulsory):** перше звернення до даних (холодний старт).
* **Ємнісний (Capacity):** обсяг кешу замалий для збереження всіх даних програми.
* **Конфліктний (Conflict):** кілька блоків змагаються за один і той самий рядок або групу.

### 5. Write-Through vs Write-Back

* **Write-Through (Наскрізний):** запис іде одночасно в кеш та в RAM. Надійно, але повільніше.
* **Write-Back (Зворотний):** запис іде тільки в кеш (ставиться прапорець *dirty*). У RAM дані скидаються лише при витісненні рядка. Швидше.

### 6. Сторінковий промах (Page Fault)

Виникає, коли потрібна віртуальна сторінка відсутня в RAM і лежить на диску.

**Небезпека:** диск у тисячі разів повільніший за RAM, тому процес зупиняється на час читання з диска, що різко знижує швидкість програми.

### 7. Графік часу доступу та логарифмічна вісь

* **Східчастий вигляд:** кожна сходинка - це вихід за межі чергового рівня пам'яті ($L1 \rightarrow L2 \rightarrow L3 \rightarrow RAM \rightarrow Disk$).
* **Логарифмічний масштаб:** обсяги пам'яті відрізняються в мільйони разів, тому в лінійній шкалі малі кеші злилися б у нуль.

### 8. Формули бітів Offset та VPN

* $\text{Offset bits} = \log_2(\text{Page\_Size})$
* $\text{VPN bits} = \text{Address\_Bits} - \text{Offset bits}$
* *Приклад (32-біт адреса, сторінка 4 КБ = $2^{12}$ Б):* $\text{Offset} = 12$ біт, $\text{VPN} = 32 - 12 = 20$ біт.

### 9. TLB-промах vs Page Fault

* **TLB-промах:** трансляції адреси немає в TLB, але сама сторінка є в RAM (обробляється швидко).
* **Page Fault:** сторінки немає в RAM, вона на диску (обробляється дуже повільно).
* **Перше звернення:** адреса ще ніколи не транслювалася, тому її трансляції гарантовано немає в кеші TLB.

## Домашнє завдання

### 1. Ієрархія пам’яті

| Рівень пам'яті | Обсяг | Затримка |
| --- | --- | --- |
| **Регістри** | $< 1\text{ КБ}$ | $< 1\text{ нс}$ |
| **L1 Кеш** | $32 - 64\text{ КБ}$ | $\sim 1\text{ нс}$ |
| **L2 Кеш** | $512\text{ КБ} - 2\text{ МБ}$ | $\sim 3 - 5\text{ нс}$ |
| **L3 Кеш** | $8 - 96\text{ МБ}$ | $\sim 10 - 20\text{ нс}$ |
| **DRAM (RAM)** | $8 - 64\text{ ГБ}$ | $\sim 50 - 100\text{ нс}$ |
| **Диск (SSD / HDD)** | $256\text{ ГБ} - 2+\text{ ТБ}$ | $50\text{ мкс} - 10\text{ мс}$ |

### 2. Обхід `int a[100][100]` у C

У мові C масиви зберігаються за рядками.

* **Зовнішній цикл по рядках (`a[i][j]`):** елементи обходяться послідовно в пам'яті $\rightarrow$ працює **просторова локальність** $\rightarrow$ мінімум промахів кешу.
* **Зовнішній цикл по стовпцях (`a[j][i]`):** стрибки через 100 елементів $\rightarrow$ руйнується локальність $\rightarrow$ багато промахів.

### 3. Витіснення «брудного» рядка

* **Write-Back:** оскільки рядок «брудний» (*dirty*), його перед витісненням **обов'язково записують у RAM**, бо там зберігається застаріла версія.
* **Write-Through:** прапорця *dirty* немає, бо RAM оновлювалася одразу при записі. Рядок просто витирається з кешу.
